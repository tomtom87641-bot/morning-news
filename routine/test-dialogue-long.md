これは動作確認です。掛け合い（対話）形式を、実際の長さ（十五分から二十分）で試し、間延びしないかを確かめます。ニュース・メール・カレンダー・Googleドライブには一切触れないでください（下の素材は既に集め終わった原稿なので、新しく検索する必要はありません）。有料の音声ツールは使わないでください。作業ファイルは `$HOME/work/` に置き、リポジトリには書き込まないでください。書き込みは新しいブランチ `claude/dialogue-long-test` だけ。`main` と `claude/feed` には push しないでください。

【声の設定（前回の実験で決定済み）】
- ミナミ（進行役）＝声 `jf_alpha`、速度 `1.0`
- カケル（質問・相槌役）＝声 `jm_kumo`、速度 `1.15`

【手順】

1. `bash scripts/setup_cloud.sh` を実行する（2〜3分）。

2. `git show origin/claude/feed:episodes/2026-09-22.txt` で、すでに集め終わった今日のニュース原稿（一人語り版、六分野）を取得し、`$HOME/work/source.txt` に保存する。

3. その原稿の内容（事実・数字・出典はすべてそのまま使う。新しい事実を足さない、変えない）をもとに、ミナミとカケルの掛け合い形式に書き直す。書き方：
   - 一つの分野が終わるごとに、ミナミが次の分野へ話を移す一言を入れる（例：「続いて、エーアイの話題です。」）。
   - 各話題は、ミナミが事実を伝え、カケルが「それってどういうことですか」「なんでそうなったんですか」のような質問をし、ミナミが補足する、という往復を基本にする。相槌や短い感想（「へえ」「なるほど」）も混ぜて、機械的な往復にしない。
   - 六分野すべてを、原稿にある話題を漏らさず対話に変換する（話題を減らさない。すべての事実を使う）。
   - 冒頭は「ミナミ：おはようございます。」から始め、原稿にある曜日・日付のあいさつを踏まえる。最後は「ミナミ：以上、今日のニュースでした。よい一日をお過ごしください。」で締める。
   - 算用数字とアルファベットは使わない（仮名か漢字で書く）。
   - 台本は `ミナミ：（せりふ）` `カケル：（せりふ）` の行を交互に並べる形式で、`$HOME/work/dialogue.txt` に保存する。

4. 台本の行数を数えて報告する（`grep -c "：" "$HOME/work/dialogue.txt"`）。

5. 台本を1行ずつ読み、話者ごとに次の声で合成する（Kokoro、`is_phonemes=True`、misakiの日本語G2P）。
   - ミナミ → 声 `jf_alpha`、速度 `1.0`
   - カケル → 声 `jm_kumo`、速度 `1.15`
   話者の切り替えの前後には0.2秒の無音を挟む（`scripts/audio.py` の `concat_with_pauses`）。全部つなげて、モノラル・48kbpsのmp3にする。出力先は `$HOME/work/out/dialogue_long.mp3`。

6. mp3の長さ（秒）とファイルサイズを標準出力に報告する。**長さが十五分（九百秒）未満、または二十分（千二百秒）を超える場合は、その旨と、目安との差を報告する（作り直さなくてよい。今回は間延びの有無を見るのが目的）**。

7. `git fetch origin && git checkout -b claude/dialogue-long-test origin/main` を実行し、`dialogue_long.mp3` を `samples/dialogue_long.mp3` としてコピーし、台本 `dialogue.txt` も `samples/dialogue_long.txt` としてコピーする。`git add samples/dialogue_long.mp3 samples/dialogue_long.txt` → `git commit -m "Add long-form dialogue test"` → `git push -u origin claude/dialogue-long-test` を実行する。push の結果を報告する。

8. 最後に、台本の中で「ミナミ：」「カケル：」の発言回数のバランス（ミナミが極端に長く話し続けている箇所が無いか）を、目視で確認して報告する。
